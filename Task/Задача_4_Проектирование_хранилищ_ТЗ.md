## **Техническое Задание (Версия 2.0): Модуль Проектирования Хранилищ (Задача №4)**

**Исполнитель**: Сергей.Н (Тимлид)
**Ветка Git**: `feature/warehouse-design`

### **1. Цель и концепция**

Разработать интеллектуальный модуль `warehouse_designer`, который автоматизирует процесс проектирования оптимального хранилища данных. Модуль будет выполнять три ключевые функции:
1.  **Анализ**: Изучение метаданных существующего источника, бизнес-требований пользователя и **результатов работы других задач**.
2.  **Проектирование**: Выбор оптимальной СУБД (PostgreSQL, ClickHouse, HDFS) и генерация соответствующей схемы данных (DDL), **учитывая рекомендации по оптимизации**.
3.  **Загрузка**: Создание и запуск ETL-пайплайна в Airflow для переноса данных из источника в новое, спроектированное хранилище.

**Уровень реализации**: **Средний**. Основной фокус — на интеллектуальном **селекторе СУБД** и генерации базового DDL.

### **2. Архитектурное место в системе**

*   Все новые файлы для этого модуля будут размещаться в новой, изолированной директории: `backend/app/warehouse_designer/`.
*   Интеграция с основной системой будет происходить исключительно через API и прямой доступ к общей базе данных PostgreSQL для чтения метаданных.

### **3. Переиспользуемые модули**

*   `profiler.py`: Для получения первичного профиля данных.
*   `database.py`: Для доступа к сессии SQLAlchemy (`get_db`) и **чтения артефактов из общих таблиц**.
*   `agent.py`: Для взаимодействия с LLM.
*   `dag_compiler.py` и шаблоны Jinja2: Как основа для генерации DDL и DAG'ов.

### **4. Входные данные (Детализировано)**

Модуль будет принимать на вход комплексную информацию.

#### **4.1. Системные данные (извлекаются автоматически из общих источников)**

1.  **Профиль источника данных (из `data_profiles` в PostgreSQL):**
    *   **Источник**: Таблица `data_profiles`, заполняемая `data_profiling_dag.py`.
    *   **Данные**: Схема, типы колонок, количество строк, примеры данных.
    *   **Как получить**: `db.query(DataProfile).filter(DataProfile.id == source_profile_id).first()`

2.  **Результаты Задачи 1 (Валидация и Качество):**
    *   **Источник**: Новое поле `quality_score: float` в таблице `data_profiles`, которое будет обновляться модулем Задачи 1.
    *   **Данные**: Оценка качества данных. Низкий `quality_score` может стать фактором для выбора HDFS (для "грязных" сырых данных).
    *   **Как получить**: Читается вместе с профилем источника данных.

3.  **Результаты Задачи 2 (Агрегация):**
    *   **Источник**: Новая таблица `aggregation_scenarios` в PostgreSQL, создаваемая модулем Задачи 2.
    *   **Данные**: Схемы агрегаций, типы (`GROUP BY`, `JOIN`), частота обновлений. Наличие сложных агрегаций — ключевой фактор для выбора ClickHouse.
    *   **Как получить**: `db.query(AggregationScenario).filter(AggregationScenario.source_id == source_profile_id).all()`

4.  **Результаты Задачи 3 (Оптимизация):**
    *   **Источник**: Новая таблица `optimization_recommendations` в PostgreSQL, создаваемая модулем Задачи 3.
    *   **Данные**: Рекомендации по партиционированию (`partition_by`), индексам (`indexes`), ключам сортировки (`order_by`) для конкретных таблиц.
    *   **Как получить**: `db.query(OptimizationRecommendation).filter(...).all()`. Эти рекомендации будут напрямую встраиваться в генерируемый DDL.

#### **4.2. Пользовательские данные (предоставляются через API)**

*   **Бизнес-требования**: Текстовое описание на естественном языке.
*   **Требования к аналитике**: Структурированное описание паттернов нагрузки.
*   **Ограничения**: Технические и операционные рамки.

### **5. Выходные данные (Артефакты)**

1.  **DDL-скрипты**: Готовые к выполнению SQL-скрипты, **включающие в себя рекомендации по партиционированию и индексам от Задачи 3**.
2.  **ETL-пайплайн**: Динамически сгенерированный DAG для Airflow.
3.  **Архитектурное резюме**: Markdown-файл с обоснованием выбора.
4.  **Запись в БД**: Новый `design_id` в таблице `warehouse_designs`.
5.  **Метрики хранилища**: API-эндпоинт для предоставления метрик **модулю Задачи 3**.

### **6. API Endpoints (Детализировано)**

*   `POST /api/v1/warehouse/design`: Запускает процесс проектирования.
*   `GET /api/v1/warehouse/design/{design_id}`: Проверка статуса и получение результатов.
*   `POST /api/v1/warehouse/create/{design_id}`: Выполнение DDL.
*   `POST /api/v1/warehouse/load-data/{design_id}`: Запуск ETL.
*   `GET /api/v1/warehouse/metrics/{table_name}`: **(Изменено)** Эндпоинт для предоставления метрик (размер, кол-во строк) модулю Задачи 3. Принимает `table_name`, а не `design_id` для большей гибкости.

# Шаг 1: Найти или создать DataProfile
$profile_id = $null
$inventory = Invoke-RestMethod -Uri "http://localhost:8000/api/data-inventory"
$existing_profile = $inventory.data | Where-Object { $_.source_path -eq "/data/raw/sales.csv" }

if ($existing_profile) {
    $profile_id = $existing_profile.id
    Write-Host "Found existing DataProfile with ID: $profile_id"
} else {
    Write-Host "No existing profile found. Creating a new one..."
    $profileBody = @{ source_path = "/data/raw/sales.csv" } | ConvertTo-Json
    $profile = Invoke-RestMethod -Uri "http://localhost:8000/api/v1/data-profiles" `
                                 -Method POST `
                                 -ContentType "application/json" `
                                 -Body $profileBody
    $profile_id = $profile.id
    Write-Host "Created new DataProfile with ID: $profile_id"
}

# Шаг 2: Запускаем новый процесс проектирования
Write-Host "Starting new design process..."
$designBody = Get-Content -Path "request_payloads/design_request.json" -Encoding Utf8 -Raw | ConvertFrom-Json
$designBody.source_profile_id = $profile_id
$designBodyJson = $designBody | ConvertTo-Json
$design = Invoke-RestMethod -Uri "http://localhost:8000/api/v1/warehouse/design" -Method POST -ContentType "application/json" -Body $designBodyJson
$design_id = $design.design_id
Write-Host "Started Design Process. New Design ID: $design_id"

# Шаг 3: Подтверждаем выбор
Write-Host "Confirming design..."
Invoke-RestMethod -Uri "http://localhost:8000/api/v1/warehouse/design/$design_id/confirm" -Method POST -ContentType "application/json" -InFile "request_payloads/confirm_request.json"
Write-Host "Design Confirmed."

# Шаг 4: Создаем таблицы
Write-Host "Creating tables..."
Invoke-RestMethod -Uri "http://localhost:8000/api/v1/warehouse/create/$design_id" -Method POST
Write-Host "Tables Created."

# Шаг 5: Генерируем DAG
Write-Host "Generating DAG..."
$response = Invoke-RestMethod -Uri "http://localhost:8000/api/v1/warehouse/load-data/$design_id" -Method POST
Write-Host "DAG Generation Triggered for DAG: $($response.dag_id)"
Write-Host "--- Test Complete ---"
