## **1. Цель и концепция**

Разработать интеллектуальный модуль `data_validator`, который автоматизирует процесс валидации, оценки качества и очистки данных. Модуль будет выполнять четыре ключевые функции:

1. **Валидация**: Проверка типов данных, выявление пропусков, дубликатов и аномалий
2. **Оценка качества**: Статистический анализ и присвоение оценки качества данных
3. **Очистка**: Автоматическое исправление найденных проблем
4. **Подготовка к хранению**: Генерация рекомендаций по оптимальному хранению

**Уровень реализации**: **Средний**. Основной фокус — на статистическом анализе аномалий и рекомендациях по хранению.

## **2. Архитектурное место в системе**

- Все новые файлы для этого модуля будут размещаться в новой, изолированной директории: `backend/app/data_validator/`
- Интеграция с основной системой будет происходить исключительно через API и прямой доступ к общей базе данных PostgreSQL для сохранения результатов
- Модуль является первым звеном в цепочке обработки данных перед модулями 2, 3, 4

## **3. Источники данных**

### **3.1. Файловые источники (data_landing_zone)**
- **Сырые данные**: `data_landing_zone/raw/` - необработанные файлы
- **Тестовые данные**: `data_landing_zone/syn_csv/`, `data_landing_zone/syn_json/`, `data_landing_zone/syn_xml/`
- **Поддерживаемые форматы**: CSV, JSON, XML, Parquet
- **Интеграция с Модулем 5**: Использование `GET /api/v1/metrics/auto-detect` для автоопределения типов данных

### **3.2. Базы данных**
- **PostgreSQL**: Прямое подключение для валидации таблиц
- **ClickHouse**: HTTP API для анализа больших таблиц
- **HDFS**: WebHDFS API для анализа распределенных данных

### **3.3. Проверка однородности файлов**
**Критическая функция**: Анализ папок с данными на предмет однородности структуры файлов.

**Алгоритм проверки однородности:**
1. Сканирование всех файлов в папке
2. Анализ схемы каждого файла (колонки, типы данных)
3. Сравнение схем между файлами
4. При обнаружении неоднородности:
   - Создание новой папки `{original_folder}_inconsistent/`
   - Перенос неоднородных файлов в новую папку
   - Логирование действий и причин разделения

**Критерии однородности:**
- Одинаковое количество колонок
- Совпадающие имена колонок (с учетом регистра)
- Совместимые типы данных (int64/int32 считаются совместимыми)
- Одинаковый разделитель для CSV файлов

## **4. Базовый набор методов предварительной подготовки данных**

### **4.1. Валидация данных**
1. **Проверка типов данных**
   - Валидация соответствия объявленных и фактических типов
   - Обнаружение некорректных значений (например, текст в числовых полях)
   - Проверка форматов дат и времени

2. **Анализ пропущенных значений**
   - Подсчет количества и процента пропусков по колонкам
   - Анализ паттернов пропусков (случайные, систематические)
   - Оценка критичности пропусков для бизнес-логики

3. **Обнаружение дубликатов**
   - Поиск полных дубликатов строк
   - Поиск частичных дубликатов по ключевым полям
   - Анализ потенциальных дубликатов с незначительными различиями

4. **Проверка целостности данных**
   - Валидация внешних ключей
   - Проверка бизнес-правил (например, дата окончания > дата начала)
   - Анализ диапазонов значений

### **4.2. Статистический анализ аномалий (средний уровень)**
1. **Выбросы в числовых данных**
   - Метод межквартильного размаха (IQR)
   - Z-score анализ (значения > 3 стандартных отклонений)
   - Isolation Forest для многомерных выбросов

2. **Аномалии в категориальных данных**
   - Редкие категории (частота < 1%)
   - Неожиданные значения в справочниках
   - Анализ распределения категорий

3. **Временные аномалии**
   - Пропуски в временных рядах
   - Неожиданные скачки значений
   - Сезонные аномалии

4. **Структурные аномалии**
   - Неожиданные изменения в схеме данных
   - Аномальные размеры файлов
   - Нарушения в форматах данных

### **4.3. Очистка данных**
1. **Исправление типов данных**
   - Автоматическое приведение к правильным типам
   - Парсинг дат в различных форматах
   - Нормализация числовых значений

2. **Обработка пропущенных значений**
   - Заполнение медианой/модой для числовых/категориальных данных
   - Интерполяция для временных рядов
   - Удаление строк с критическими пропусками

3. **Удаление/объединение дубликатов**
   - Автоматическое удаление точных дубликатов
   - Интеллектуальное объединение частичных дубликатов
   - Сохранение истории изменений

4. **Нормализация данных**
   - Стандартизация форматов (даты, телефоны, адреса)
   - Приведение к единому регистру
   - Удаление лишних пробелов и символов

### **4.4. Рекомендации по хранению (интеграция с другими модулями)**
1. **Анализ качества для выбора СУБД**
   - `quality_score < 0.7` → рекомендация HDFS (для "грязных" данных)
   - `quality_score >= 0.7 && complex_analytics` → рекомендация ClickHouse
   - `quality_score >= 0.8 && transactional` → рекомендация PostgreSQL

2. **Рекомендации по структуре**
   - Предложения по партиционированию на основе анализа данных
   - Рекомендации по индексам для часто используемых полей
   - Советы по сжатию на основе типов данных

- **Полнота данных** (40%): процент заполненных значений
- **Корректность** (30%): соответствие типам и форматам
- **Согласованность** (20%): отсутствие противоречий
- **Уникальность** (10%): отсутствие дубликатов

**Назначение:** Статистический анализ аномалий (средний уровень)

**Назначение:** Обнаружение статистических аномалий в данных

**Методы обнаружения:**
1. **IQR метод** для числовых данных
2. **Z-score анализ** для выбросов
3. **Isolation Forest** для многомерных аномалий
4. **Частотный анализ** для категориальных данных

### **6.4. HomogeneityChecker (homogeneity_checker.py)**
**Назначение:** Проверка однородности файлов в папках

#### `check_folder_homogeneity(folder_path: str) -> HomogeneityResult`
**Назначение:** Анализ однородности файлов в папке

**Процесс проверки:**
1. Сканирование всех файлов в папке
2. Извлечение схемы каждого файла
3. Сравнение схем между файлами
4. Создание отчета о неоднородности
5. Автоматическое разделение неоднородных файлов

### **6.5. StorageRecommender (storage_recommender.py)**
**Назначение:** Генерация рекомендаций по хранению данных

#### `generate_storage_recommendations(quality_assessment: QualityAssessment, data_profile: dict) -> List[StorageRecommendation]`
**Назначение:** Создание рекомендаций по оптимальному хранению

**Типы рекомендаций:**
- **Выбор СУБД**: PostgreSQL, ClickHouse, HDFS
- **Партиционирование**: по датам, категориям
- **Индексирование**: для часто используемых полей
- **Сжатие**: на основе типов данных

## **10. Алгоритмы и логика**

### **10.1. Алгоритм оценки качества данных**
```python
def calculate_quality_score(df: pd.DataFrame) -> float:
    completeness = 1 - df.isnull().sum().sum() / (df.shape[0] * df.shape[1])
    correctness = calculate_type_correctness(df)
    consistency = calculate_consistency_score(df)
    uniqueness = 1 - calculate_duplicate_ratio(df)
    
    quality_score = (
        completeness * 0.4 +
        correctness * 0.3 +
        consistency * 0.2 +
        uniqueness * 0.1
    )
    return min(max(quality_score, 0.0), 1.0)
```

### **10.2. Алгоритм проверки однородности**
```python
def check_homogeneity(folder_path: str) -> HomogeneityResult:
    files = scan_folder(folder_path)
    schemas = [extract_schema(file) for file in files]
    
    reference_schema = schemas[0]
    inconsistent_files = []
    
    for i, schema in enumerate(schemas[1:], 1):
        if not schemas_compatible(reference_schema, schema):
            inconsistent_files.append(files[i])
    
    if inconsistent_files:
        move_inconsistent_files(inconsistent_files, folder_path)
    
    return HomogeneityResult(
        homogeneous=len(inconsistent_files) == 0,
        inconsistent_files=inconsistent_files
    )
```

### **10.3. Алгоритм генерации рекомендаций по хранению**
```python
def recommend_storage(quality_score: float, data_profile: dict) -> str:
    if quality_score < 0.7:
        return "hdfs"  # Для "грязных" данных
    
    if has_complex_analytics(data_profile) and quality_score >= 0.7:
        return "clickhouse"  # Для аналитики
    
    if is_transactional(data_profile) and quality_score >= 0.8:
        return "postgresql"  # Для OLTP
    
    return "postgresql"  # По умолчанию
```
