## **ЗАДАЧА 1: Модуль валидации, оценки качества и очистки данных**
**Исполнитель**: Алексей


### **Описание**
Вам необходимо создать интеллектуальный модуль для автоматической валидации имеющихся данных, выявления аномалий и их очистки. Этот модуль будет первым звеном в цепочке обработки данных перед их загрузкой в проектируемое мной хранилище.

### **Критические требования от тимлида**
⚠️ **ВАЖНО**: Ваш модуль должен подготавливать данные в строго определенных форматах для загрузки в хранилище:
- **Очищенные файлы** сохранять в `data_landing_zone/cleaned/{source_name}/` в формате Parquet
- **Обязательные метаданные** для каждого очищенного файла: `schema_version`, `cleaning_timestamp`, `quality_score`, `row_count_before`, `row_count_after`
- **Отчеты о качестве** в JSON формате с полями: `data_source`, `quality_issues`, `applied_fixes`, `recommendations`

### **Интеграция с хранилищем**
Отчеты о качестве нужны для:
- Автоматического выбора оптимальной СУБД (PostgreSQL/ClickHouse/HDFS)
- Создания правил партиционирования на основе качества данных
- Настройки индексов для часто проверяемых полей

### **API требования**
```python
# Обязательные endpoints для интеграции
POST /api/v1/data-quality/validate/{profile_id}
# Response: {"quality_score": float, "issues": [], "recommended_storage": "clickhouse|postgres|hdfs"}

POST /api/v1/data-quality/clean/{profile_id}  
# Response: {"cleaned_file_path": str, "metadata": {}, "storage_recommendations": {}}
```

### **Уровни реализации**
1. **Базовый (2-3 часа)**: Валидация типов данных, пропусков, дубликатов + генерация метаданных
2. **Средний (3-4 часа)**: Статистический анализ аномалий + рекомендации по хранению
3. **Продвинутый (3-4 часа)**: LLM-анализ семантических проблем + автоматические исправления
4. **Экспертный (1-2 часа)**: Интеграция с общим API хранилища для передачи рекомендаций

## **ЗАДАЧА 2: Модуль интеллектуальной агрегации и обогащения данных**
**Исполнитель**: Разработчик 2

### **Описание**
Создайте систему для агрегации данных из множественных источников и их обогащения. Ваш модуль будет работать с очищенными данными от Разработчика 1 и подготавливать агрегированные датасеты для загрузки в мое хранилище.

### **Критические требования от тимлида**
⚠️ **ВАЖНО**: Ваши агрегированные данные должны соответствовать архитектуре хранилища:
- **Выходной формат**: Parquet файлы в `data_landing_zone/aggregated/{scenario_name}/`
- **Обязательная схема метаданных**: `aggregation_type`, `source_tables`, `join_keys`, `aggregation_functions`, `target_schema`
- **Совместимость с ClickHouse**: все агрегации должны быть совместимы с ClickHouse движками (MergeTree, AggregatingMergeTree)

### **Интеграция с хранилищем**
Ваши результаты будут нужны для:
- Автоматического создания материализованных представлений в ClickHouse
- Настройки оптимальных движков таблиц на основе типов агрегаций
- Создания ETL пайплайнов для регулярного обновления агрегатов

### **Требования к DAG генерации**
- Генерируемые Airflow DAG'и должны включать задачу уведомления моего модуля о готовности данных
- Используйте шаблон: `generated_aggregation_{scenario_name}_{timestamp}.py`
- Обязательный callback: `POST /api/v1/warehouse/notify-data-ready`

### **API требования**
```python
POST /api/v1/aggregation/create-scenario
# Request: {"sources": [], "aggregations": [], "target_schema": {}, "schedule": ""}
# Response: {"scenario_id": str, "estimated_target_size": int, "recommended_engine": str}

POST /api/v1/aggregation/execute/{scenario_id}
# Response: {"execution_id": str, "output_path": str, "target_table_ddl": str}
```

### **Уровни реализации**
1. **Базовый (2-3 часа)**: Простые агрегации (GROUP BY, SUM, AVG) + метаданные для хранилища
2. **Средний (3-4 часа)**: Многотабличные JOIN'ы + валидация совместимости схем
3. **Продвинутый (3-4 часа)**: LLM-генерация DAG'ов + оптимизация под ClickHouse
4. **Экспертный (1-2 часа)**: Чат-интерфейс + автоматическое создание таблиц в хранилище

## **ЗАДАЧА 3: Модуль оптимизации производительности обработки данных**
**Исполнитель**: Разработчик 3

### **Описание**
Разработайте систему мониторинга и оптимизации производительности. Ваш модуль будет анализировать метрики использования хранилища и предлагать оптимизации.

### **Критические требования от тимлида**
⚠️ **ВАЖНО**: Ваш модуль должен работать с реальными метриками моего хранилища:
- **Источники метрик**: PostgreSQL `pg_stat_statements`, ClickHouse `system.query_log`, HDFS namenode metrics
- **Обязательный мониторинг**: время выполнения запросов, использование индексов, размеры партиций, частота обращений
- **Формат рекомендаций**: DDL скрипты готовые к выполнению + обоснование от LLM

### **Интеграция с хранилищем**
Вместе сделаем:
- Доступ к метрикам производительности через общий API
- Схемы всех таблиц для анализа
- Статистику использования для принятия решений об оптимизации

Вы должны предоставить мне:
- Готовые DDL скрипты для создания индексов и партиций
- Рекомендации по реструктуризации таблиц
- Автоматические триггеры оптимизации

### **Требования к безопасности**
- Все DDL операции должны проходить через общий модуль для валидации
- Обязательная проверка влияния на производительность перед применением
- Возможность отката изменений

### **API требования**
```python
GET /api/v1/performance/metrics/{table_name}
# Response: {"query_stats": {}, "index_usage": {}, "partition_stats": {}}

POST /api/v1/performance/analyze/{table_name}
# Response: {"bottlenecks": [], "recommendations": [], "ddl_scripts": []}

POST /api/v1/performance/optimize/{table_name}
# Request должен включать подтверждение от warehouse API
```

### **Уровни реализации**
1. **Базовый (2-3 часа)**: Сбор метрик производительности + базовая аналитика
2. **Средний (3-4 часа)**: Автогенерация индексов и партиций + валидация
3. **Продвинутый (3-4 часа)**: LLM-анализ паттернов использования + комплексные рекомендации
4. **Экспертный (1-2 часа)**: Автоматическое применение оптимизаций + интеграция с общим API
