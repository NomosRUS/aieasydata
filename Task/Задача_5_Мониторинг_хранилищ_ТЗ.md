# ЗАДАЧА 5: Модуль мониторинга и сбора метрик хранилищ

**Исполнитель**: Разработчик 5 (или текущий исполнитель)

### **Описание**

Разработайте независимый, переиспользуемый сервис для сбора реальных метрик производительности и состояния с различных хранилищ данных. Этот модуль будет выступать в роли поставщика данных (Data Provider) для других интеллектуальных систем, в первую очередь для **Модуля 3 (Оптимизация производительности)**.

Модуль должен быть архитектурно изолирован и не зависеть от логики других компонентов, таких как `warehouse_designer`.

### **Критические требования от тимлида**

⚠️ **ВАЖНО**: Ваш модуль должен быть универсальным и работать как внешний диагностический инструмент.

-   **Архитектурная изоляция**: Модуль должен располагаться в собственной папке (`backend/app/metrics_collector`) и не иметь прямых зависимостей от `warehouse_designer`.
-   **Прямое подключение**: Модуль должен подключаться напрямую к целевым базам данных (PostgreSQL, ClickHouse) для сбора метрик из их системных представлений.
-   **Сбор реальных метрик**: Необходимо собирать как статические метрики (количество строк, размер на диске), так и динамические метрики производительности (среднее время выполнения запроса).
-   **Гибкий API**: API модуля должен позволять запрашивать метрики для любого хранилища, передавая ему необходимые параметры для подключения.

### **Интеграция с другими модулями**

-   **Входные данные**: Информация для подключения к целевой БД, передаваемая через API. Структура `ConnectionInfo`:
    -   `db_type`: `str` ('clickhouse' или 'postgres')
    -   `host`: `str`
    -   `port`: `int`
    -   `user`: `str`
    -   `password`: `str`
    -   `db_name`: `str`
    -   `table_name`: `str`
    -   `design_id`: `str` (опционально, для связи с проектом)

-   **Выходные данные**: API-эндпоинт, возвращающий JSON-объект с собранными метриками.
    -   **Эндпоинт**: `POST /api/v1/metrics/collect`
    -   **Ответ**: `{"row_count": int, "size_in_bytes": int, "avg_query_duration_ms": float, ...}`

### **Этапы реализации**

#### **Этап 1: Создание архитектурной основы модуля (0.5 часа)**

1.  **Действия:**
    *   Создать директорию `backend/app/metrics_collector`.
    *   Внутри создать файлы: `__init__.py`, `main.py` (логика), `router.py` (API), `schemas.py` (модели).
    *   В `shared/schemas.py` создать SQLAlchemy-модель `WarehouseInstance` для персистентного хранения метрик.
    *   Подключить новый роутер из `metrics_collector/router.py` в главном файле `backend/app/main.py`.

2.  **Диагностика перехода:**
    *   ✅ Структура папок и файлов создана.
    *   ✅ Новый роутер подключен, приложение запускается без ошибок.

#### **Этап 2: Реализация ядра сбора метрик (1.5 часа)**

1.  **Действия:**
    *   В `metrics_collector/schemas.py` определить Pydantic-модели `ConnectionInfo` и `WarehouseMetrics`.
    *   В `metrics_collector/main.py` реализовать основную функцию `collect_metrics(conn_info: ConnectionInfo) -> dict`.
    *   Внутри `collect_metrics` реализовать логику подключения к ClickHouse и PostgreSQL.
    *   Реализовать SQL-запросы к `system.parts` (ClickHouse) и `pg_class` (PostgreSQL) для сбора базовых метрик (размер, кол-во строк).
    *   Реализовать SQL-запросы к `system.query_log` (ClickHouse) и `pg_stat_statements` (PostgreSQL) для сбора метрик производительности.

2.  **Диагностика перехода:**
    *   ✅ Написать unit-тест для функции `collect_metrics`, который проверяет корректность сбора метрик с mock-соединениями.

#### **Этап 3: Создание и интеграция API (1 час)**

1.  **Действия:**
    *   В `metrics_collector/router.py` создать эндпоинт `POST /api/v1/metrics/collect`.
    *   Реализовать логику, которая вызывает `collect_metrics` и, если в запросе передан `design_id`, сохраняет результат в таблицу `WarehouseInstance`.
    *   В `warehouse_designer/router.py` создать эндпоинт `GET /api/v1/warehouse/instances`, который возвращает все сохраненные экземпляры хранилищ с их метриками.

2.  **Диагностика перехода:**
    *   ✅ Провести полный E2E-тест: создать хранилище через `warehouse_designer`, затем вызвать `POST /api/v1/metrics/collect` для сбора его метрик. Убедиться, что метрики сохранились.
    *   ✅ Вызвать `GET /api/v1/warehouse/instances` и проверить, что он возвращает корректные данные.
    *   ✅ Код готов к Pull Request.
