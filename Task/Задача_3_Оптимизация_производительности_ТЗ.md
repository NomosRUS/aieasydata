# **Техническое Задание: Модуль Оптимизации Производительности (Задача №3)**

**Исполнитель**: Разработчик 3  
**Ветка Git**: `feature/performance-optimization`  
**Уровень реализации**: **Средний** - Автогенерация индексов и партиций + валидация

## **1. Цель и концепция**

Разработать интеллектуальный модуль `performance_optimizer`, который автоматизирует процесс мониторинга и оптимизации производительности хранилищ данных. Модуль будет выполнять четыре ключевые функции:

1. **Сбор метрик**: Получение реальных метрик производительности из различных источников данных через интеграцию с **Модулем 5 (Мониторинг)**
2. **Анализ производительности**: Выявление узких мест и проблем производительности с использованием ИИ-анализа
3. **Генерация рекомендаций**: Автоматическое создание DDL-скриптов для индексов, партиций и других оптимизаций
4. **Валидация и применение**: Безопасное применение оптимизаций с возможностью отката

**Ключевая особенность**: Модуль использует **автоопределение типов данных из Модуля 5** для автоматического анализа любых источников данных без предварительной настройки.

## **2. Архитектурное место в системе**

- Все новые файлы для этого модуля размещаются в новой, изолированной директории: `backend/app/performance_optimizer/`
- Интеграция с системой происходит через API и прямой доступ к общей базе данных PostgreSQL
- **Основной источник данных**: Модуль 5 через API `/api/v1/metrics/auto-detect` для автоматического получения метрик
- **Интеграция с Модулем 4**: Сохранение рекомендаций в таблицу `optimization_recommendations` для использования при проектировании хранилищ

## **3. Переиспользуемые модули**

- **Модуль 5 (metrics_collector)**: Основной источник метрик через автоопределение типов данных
- `database.py`: Для доступа к сессии SQLAlchemy (`get_db`) и сохранения рекомендаций
- `agent.py`: Для взаимодействия с LLM при анализе производительности и генерации обоснований
- **Модуль 4 (warehouse_designer)**: Для получения информации о существующих хранилищах

## **4. Входные данные**

### **4.1. Автоматические источники данных (через Модуль 5)**

1. **Автоопределение источников данных**:
   - **API**: `GET /api/v1/metrics/auto-detect?source={data_source}`
   - **Поддерживаемые источники**: CSV, JSON, XML, Parquet файлы, PostgreSQL БД, ClickHouse БД, директории
   - **Автоопределение**: разделители CSV, форматы JSON/JSON Lines, теги XML записей, строки подключения БД
   - **Получаемые метрики**: размер данных, количество строк, структура, производительность обработки

2. **Метрики созданных хранилищ (интеграция с Модулем 4)**:
   - **API**: `POST /api/v1/metrics/collect-by-design/{design_id}`
   - **Источник**: Реальные подключения к ClickHouse и PostgreSQL из созданных в Модуле 4 хранилищ
   - **Данные**: время выполнения запросов, использование индексов, размеры партиций, статистика обращений
   - **Интеграция**: автоматическое получение параметров подключения из WarehouseInstance

3. **Файловая система**:
   - **API**: `GET /api/v1/metrics/data-landing-zone`
   - **Данные**: мониторинг папки `data_landing_zone` с автоматическим анализом всех файлов
   - **Возможности**: обработка больших файлов (>1GB), прогресс-индикаторы, graceful degradation

### **4.2. Пользовательские данные (через API)**

- **Целевой источник данных**: Путь к файлу, директории или строка подключения к БД
- **Требования к производительности**: Целевое время выполнения запросов, ожидаемая нагрузка
- **Ограничения**: Технические рамки для применения оптимизаций

## **5. Выходные данные (Артефакты)**

1. **DDL-скрипты оптимизации**: Готовые к выполнению SQL-скрипты для создания индексов и партиций
2. **Рекомендации по реструктуризации**: Предложения по изменению структуры таблиц
3. **Отчет об анализе производительности**: Markdown-файл с выявленными узкими местами и обоснованием рекомендаций
4. **Запись в БД**: Сохранение рекомендаций в таблицу `optimization_recommendations` для **интеграции с Модулем 4**
5. **Метрики до/после**: Сравнительный анализ производительности

## **6. API Endpoints**

### **6.1. Основные endpoints**

- `POST /api/v1/performance/analyze`: Запуск анализа производительности источника данных
- `GET /api/v1/performance/analysis/{analysis_id}`: Получение результатов анализа
- `POST /api/v1/performance/optimize/{analysis_id}`: Применение рекомендованных оптимизаций
- `GET /api/v1/performance/recommendations/{table_name}`: Получение рекомендаций для конкретной таблицы

### **6.2. Интеграционные endpoints**

- `GET /api/v1/performance/metrics/{source}`: Получение текущих метрик производительности (интеграция с Модулем 5)
- `POST /api/v1/performance/validate-ddl`: Валидация DDL-скриптов перед применением
- `GET /api/v1/performance/history/{table_name}`: История оптимизаций и их эффективность

## **7. Модели данных**

### **7.1. Pydantic модели (schemas.py)**

```python
class PerformanceAnalysisRequest(BaseModel):
    source: str  # Путь к файлу/директории или строка подключения к БД
    performance_requirements: Optional[Dict[str, Any]] = None
    constraints: Optional[Dict[str, Any]] = None

class PerformanceMetrics(BaseModel):
    source_type: str  # csv, json, xml, postgresql, clickhouse
    data_size_bytes: int
    row_count: int
    avg_query_time_ms: Optional[float] = None
    index_usage_stats: Optional[Dict[str, Any]] = None
    partition_stats: Optional[Dict[str, Any]] = None

class OptimizationRecommendation(BaseModel):
    recommendation_type: str  # index, partition, restructure
    target_table: str
    ddl_script: str
    estimated_improvement: float  # Ожидаемое улучшение в %
    reasoning: str  # Обоснование от LLM
    priority: str  # high, medium, low

class PerformanceAnalysisResult(BaseModel):
    analysis_id: str
    source: str
    current_metrics: PerformanceMetrics
    bottlenecks: List[str]
    recommendations: List[OptimizationRecommendation]
    status: str  # analyzing, completed, error
```

### **7.2. SQLAlchemy модели (интеграция с Модулем 4)**

Использование существующей модели `OptimizationRecommendation` из `shared/schemas.py`:

```python
class OptimizationRecommendation(Base):
    __tablename__ = "optimization_recommendations"
    
    id = Column(Integer, primary_key=True, index=True)
    table_name = Column(String, nullable=False)
    recommendation_type = Column(String, nullable=False)  # "partition", "index", "compression", "order_by"
    recommendation_details = Column(JSON, nullable=False)
    estimated_improvement = Column(Float)
    reasoning = Column(Text)
    created_at = Column(DateTime, default=datetime.utcnow)
    applied_at = Column(DateTime, nullable=True)
    
    __table_args__ = (
        UniqueConstraint('table_name', 'recommendation_type', name='uq_table_recommendation'),
    )
```

**Формат recommendation_details для разных СУБД:**

```python
# ClickHouse
{
    "partition_by": "toYYYYMM(sale_date)",
    "order_by": ["sale_date", "customer_id"]
}

# PostgreSQL  
{
    "indexes": ["customer_id", "product_name"],
    "partition_by": "RANGE (sale_date)"
}

# HDFS
{
    "partition_by": "year_month",
    "format": "parquet",
    "compression": {"type": "snappy", "block_size": "128MB"}
}
```
