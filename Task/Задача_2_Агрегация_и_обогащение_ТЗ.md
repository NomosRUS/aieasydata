## **Техническое Задание: Модуль Интеллектуальной Агрегации и Обогащения Данных (Задача №2)**

**Исполнитель**: Разработчик 2  
**Ветка Git**: `feature/data-aggregation`  
**Уровень реализации**: **Средний** - Автогенерация индексов и партиций + валидация

### **1. Цель и концепция**

Разработать интеллектуальный модуль `data_aggregator`, который автоматизирует процесс агрегации данных из множественных источников и их обогащения. Модуль будет выполнять четыре ключевые функции:

1. **Сбор данных**: Получение очищенных данных из `data_landing_zone` и подключение к реальным БД (PostgreSQL, ClickHouse, HDFS)
2. **Кастомизация**: Создание кастомизированных наборов данных из выбранных колонок разных источников
3. **Агрегация**: Выполнение сложных агрегаций (GROUP BY, JOIN, window functions) с оптимизацией под целевые СУБД
4. **Обогащение**: Добавление вычисляемых полей, метаданных и подготовка данных для модуля 4

**Ключевая особенность**: Модуль поддерживает создание **кастомизированных баз данных** из специально выбранных колонок нескольких источников, формируя микс данных в виде единого оптимизированного набора.

### **2. Архитектурное место в системе**

- Все новые файлы для этого модуля будут размещаться в новой, изолированной директории: `backend/app/data_aggregator/`
- Интеграция с основной системой будет происходить через API и прямой доступ к общей базе данных PostgreSQL
- Модуль получает данные от модуля 1 (валидация) и передает результаты в модуль 4 (проектирование хранилищ)

### **3. Переиспользуемые модули**

- `metrics_collector/main.py`: Для автоопределения типов данных и получения метрик источников
- `database.py`: Для доступа к сессии SQLAlchemy (`get_db`) и работы с метаданными
- `agent.py`: Для LLM-анализа оптимальных стратегий агрегации
- `dag_compiler.py` и шаблоны Jinja2: Для генерации ETL пайплайнов

### **4. Входные данные**

#### **4.1. Источники данных**

**Файловые источники (из data_landing_zone):**
- `data_landing_zone/cleaned/{source_name}/` - очищенные данные от модуля 1 в формате Parquet
- `data_landing_zone/raw/` - сырые данные в форматах CSV, JSON, XML
- Автоопределение типов через интеграцию с модулем 5: `GET /api/v1/metrics/auto-detect`

**Базы данных:**
- **PostgreSQL**: Подключение через строки подключения, получение схем и данных
- **ClickHouse**: HTTP API для получения данных и метаданных
- **HDFS**: Чтение Parquet файлов через WebHDFS API

### **5. Выходные данные (Артефакты)**

1. **Агрегированные данные**: Parquet файлы в `data_landing_zone/aggregated/{scenario_name}/`
2. **Метаданные агрегации**: JSON файлы с описанием схемы, источников и трансформаций
3. **DDL для целевой СУБД**: Готовые скрипты создания таблиц с оптимизациями
4. **ETL пайплайн**: Динамически сгенерированный Airflow DAG
5. **Запись в БД**: Новый `scenario_id` в таблице `aggregation_scenarios`
6. **Рекомендации оптимизации**: Предложения по индексам и партиционированию для модуля 3

### **6. API Endpoints**

#### **Основные endpoints:**

- `POST /api/v1/aggregation/create-scenario`: Создание нового сценария агрегации
- `GET /api/v1/aggregation/scenario/{scenario_id}`: Получение информации о сценарии
- `POST /api/v1/aggregation/execute/{scenario_id}`: Выполнение агрегации
- `GET /api/v1/aggregation/execution/{execution_id}`: Статус выполнения
- `POST /api/v1/aggregation/validate-scenario`: Валидация сценария перед выполнением

#### **Интеграционные endpoints:**

- `GET /api/v1/aggregation/sources`: Список доступных источников данных
- `POST /api/v1/aggregation/analyze-sources`: Анализ совместимости источников
- `GET /api/v1/aggregation/recommendations/{scenario_id}`: Рекомендации по оптимизации

#### **Кастомизация данных:**

- `POST /api/v1/aggregation/custom-dataset`: Создание кастомного набора данных
- `GET /api/v1/aggregation/column-mapping/{source_id}`: Получение доступных колонок источника
- `POST /api/v1/aggregation/preview-join`: Предварительный просмотр результата JOIN

## **Модели данных**

### **AggregationScenario (SQLAlchemy)**

```python
class AggregationScenario(Base):
    __tablename__ = "aggregation_scenarios"
    
    id = Column(Integer, primary_key=True)
    scenario_name = Column(String, unique=True, nullable=False)
    description = Column(Text)
    sources = Column(JSON)  # Список источников данных
    aggregations = Column(JSON)  # Конфигурация агрегаций
    enrichments = Column(JSON)  # Правила обогащения
    target_requirements = Column(JSON)  # Требования к целевой системе
    status = Column(String, default="created")
    created_at = Column(DateTime, default=datetime.utcnow)
    last_executed = Column(DateTime)
    execution_stats = Column(JSON)  # Статистика выполнения
```

### **Pydantic модели**

```python
class DataSource(BaseModel):
    source_id: str
    source_type: Literal["file", "postgresql", "clickhouse", "hdfs"]
    path: Optional[str] = None
    connection: Optional[str] = None
    table: Optional[str] = None
    selected_columns: List[str]
    filters: Optional[Dict[str, Any]] = None

class AggregationRule(BaseModel):
    type: Literal["join", "group_by", "window", "union"]
    parameters: Dict[str, Any]

class EnrichmentRule(BaseModel):
    type: Literal["calculated_field", "lookup", "transformation"]
    name: str
    expression: str

class AggregationScenarioRequest(BaseModel):
    name: str
    description: str
    sources: List[DataSource]
    aggregations: List[AggregationRule]
    enrichments: Optional[List[EnrichmentRule]] = []
    target_requirements: Dict[str, Any]
```

## **Алгоритмы и оптимизации**

### **Автогенерация индексов:**
1. **Анализ JOIN ключей** → автоматическое создание индексов на ключевые поля
2. **Анализ GROUP BY колонок** → составные индексы для ускорения агрегаций
3. **Анализ фильтров** → индексы на часто используемые WHERE условия

### **Автогенерация партиций:**
1. **Временные данные** → партиционирование по датам (месяц/год)
2. **Категориальные данные** → партиционирование по регионам/типам
3. **Объемные данные** → hash-партиционирование для равномерного распределения

### **Валидация совместимости:**
1. **Проверка типов данных** при JOIN операциях
2. **Анализ кардинальности** для оптимизации порядка JOIN
3. **Валидация ограничений** целевой СУБД
