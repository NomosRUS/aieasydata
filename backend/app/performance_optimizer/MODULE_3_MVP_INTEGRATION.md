## 🎯 ПРАКТИЧЕСКИЕ СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ В MVP

### **Сценарий 1: Анализ CSV файла для госуслуг**

**Пользователь загружает:** `moscow_transport_data.csv` (10M записей, 500MB)

**Модуль 3 автоматически:**
1. **Определяет тип:** CSV с временными данными
2. **Анализирует структуру:** колонки date, route_id, passenger_count
3. **Выявляет узкие места:** "Большой объем данных требует партиционирования"
4. **Рекомендует СУБД:** ClickHouse для аналитики
5. **Генерирует DDL:**
   ```sql
   CREATE TABLE moscow_transport (
       date Date,
       route_id String,
       passenger_count UInt32
   ) ENGINE = MergeTree
   PARTITION BY toYYYYMM(date)
   ORDER BY (date, route_id);
   ```
6. **Обосновывает:** "Данные временные и агрегированные – рекомендую ClickHouse с партиционированием по дате для быстрых аналитических запросов"

### **Сценарий 2: Оптимизация существующего хранилища**

**Пользователь имеет:** Таблицу в PostgreSQL с медленными запросами

**Модуль 3 автоматически:**
1. **Подключается к БД** и анализирует производительность
2. **Выявляет проблемы:** "Медленные запросы по customer_id"
3. **Рекомендует индекс:** `CREATE INDEX idx_orders_customer_id ON orders(customer_id);`
4. **Оценивает улучшение:** "Ожидаемое ускорение запросов на 75%"
5. **Предлагает валидацию** перед применением

### **Сценарий 3: Миграция данных между системами**

**Задача:** Перенести данные из CSV в оптимальное хранилище

**Модуль 3 в составе MVP:**
1. **Анализирует источник** (CSV файл)
2. **Рекомендует целевую СУБД** на основе паттернов данных
3. **Генерирует DDL** с оптимизациями
4. **Интегрируется с Модулем 4** для создания хранилища
5. **Предоставляет метрики** для мониторинга ETL
